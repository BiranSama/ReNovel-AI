# Re:Novel 重构路线图

> 本文件是无人值守重构的依据：每一轮工作都从这里选下一个未完成项，完成后勾选并写进度日志。
> 你回来后看「进度日志」即可知道做到了哪里；「默认决定」里的任何一条都可以随时推翻。

## 终点目标

一个 **Windows 上解压即用的 exe 版 Re:Novel**，在现有精修功能（单段 / 全文 / 批量）稳定可用的基础上，具备：

1. **记忆一致性**：自动整理角色、事件、章节摘要与人物关系；改写时只参考前文（不剧透），审校时能指出与前文设定冲突的地方
2. **文风**：每本书有自己的文风档案，改写时遵循，审校时打分
3. **续写**：在全书末尾或章节中续写，结合记忆与文风

并且所有核心流程都有自动化测试，CI 全绿。

## 无人值守规则

- **只在功能分支上工作**：每个阶段一个分支、一个 PR，依次叠在前一阶段之上。
  不推送 `main`、不合并任何 PR、不强推、不改写已推送的历史、不发布 Release。
- **推送前**：本地跑完全部测试（单元 + 冒烟）并全部通过；**推送后**：等 GitHub CI 通过再继续下一项。
- 测试只用假 LLM；不使用真实 API Key，不接触任何用户数据。
- 需要人来决定的问题：有「默认决定」的按默认执行并记入进度日志；没有默认、又无法安全决定的，
  跳过该项、标为「待确认」，继续做下一项。
- **停止条件**：全部阶段完成；或同一个 CI 失败连续修 3 次仍未通过；或剩下的都是「待确认」项。停止时发通知。

## 阶段与完成标准

### 阶段 0：安全网 ✅（PR #11）
冒烟测试、特征测试、锁定依赖、CI。

### 阶段 1：拆分业务层 ✅（分支 `refactor/phase1-services`）
数据目录统一、LLM 客户端换 `openai` SDK、统一精修流程、导入 / 批量 / 聊天 / 图谱服务；
修复阶段 0 记录的已知问题与 PR #11 审查发现的问题。

### 阶段 2：界面与运行时 ✅（分支 `refactor/phase2-ui`）
- [x] 页面改为页面函数：每个浏览器标签页有独立状态，不再依赖 NiceGUI 脚本模式（打包 exe 的前提）
- [x] 全局 `app_state` 拆成每个会话一份；各服务在启动入口统一创建
- [x] 阻塞调用（向量库、嵌入模型）放到线程里执行，长任务期间界面仍可操作
- [x] 设置界面：模型服务预设一键填充、「测试连接」按钮、审校模式 / 阈值 / 最多重试次数
- [x] 主界面拆成组件（编辑器、侧栏、聊天、图谱、批量、设置）

**完成标准**：两个标签页同时操作互不干扰（冒烟测试覆盖）；向量化或批量进行中界面仍能响应。

### 阶段 3：记忆一致性（分支 `refactor/phase3-memory`）—— 最高优先
- [x] 向量库改为 SQLite + numpy；已有 ChromaDB 数据可迁移
- [ ] Embedding：本地中文模型 + API 两种，可在设置里切换
- [ ] 章节记忆：每章的摘要、出场角色、关键事件；只从已保存的正文生成，内容不变则不重复生成
- [ ] 角色档案：自动汇总别名、性格、关系与状态变化，可在界面查看和手动修订
- [ ] 改写上下文只取当前章节之前的记忆（读者视角）；审校用作者视角检查 OOC、时间线、伏笔，并指出具体冲突
- [ ] 段落版本：原文 / 候选 / 已采纳，可撤销

**完成标准**：用测试小说验证——在第 N 章改写时，提示词里只出现前文信息；
审校提示词里带有与本段相关的角色设定和前文事件；以上都有测试断言。

### 阶段 4：文风（分支 `refactor/phase4-style`）
- [ ] 文风档案：从原文提炼风格描述并挑选代表段落，按项目保存，可编辑
- [ ] Writer 按文风档案改写（描述 + 示例段落）；Reviewer 增加「文风贴合度」评分
- [ ] 文风预设（如白描、古风、轻小说），可套用到项目

**完成标准**：改写和审校的提示词里包含文风档案；修改档案后下一次改写立即生效（测试覆盖）。

### 阶段 5：续写（分支 `refactor/phase5-continue`）
- [ ] 全书末尾续写新章节；章节中某段之后续写若干段；可选大纲
- [ ] 续写使用前文摘要、角色状态、未回收的伏笔与文风档案；Reviewer 检查一致性
- [ ] 续写结果是草稿，采纳后才保存并进入记忆

**完成标准**：冒烟测试走通「续写 → 审校 → 采纳 → 保存 → 记忆更新」。

### 阶段 6：exe 发布（分支 `refactor/phase6-exe`）
- [ ] GitHub Actions 在 Windows 上打包 exe，产物作为工作流附件（不发布 Release）
- [ ] 启动自检：打包产物在 Windows runner 上启动并响应页面请求
- [ ] 首次启动引导填写 API Key；更新安装与使用说明

**完成标准**：CI 产出可下载的 exe 压缩包，自检通过。
